## 2. 本次版本变更对测试的影响

结合当前项目代码与文档，测试方案需要重点更新的内容如下：

### 2.1 架构侧变化

项目当前核心技术栈已从此前的：

- Vue 3 + FastAPI + MySQL + Web3

扩展为：

- Vue 3 + FastAPI + MySQL + Ollama + Qdrant + Web3

其中新增或强化的能力包括：

1. **本地大模型接入**
   - 接入 Ollama
   - 支持普通问答与流式问答
   - 支持首页 AI 个性化建议

2. **向量 RAG 能力**
   - 新增 `rag` 功能模块
   - 使用 `nomic-embed-text` 生成 embedding
   - 使用 Qdrant 存储向量
   - `rag_knowledge_documents` 做向量化
   - 新增 `rag_knowledge_chunks` 表存放文档分块元数据

3. **管理端知识库能力增强**
   - 支持 RAG 文档手工新增/编辑/删除
   - 支持导入 PDF / DOCX 到 RAG 知识库
   - 支持查看文档 chunk 状态与向量状态
   - 支持查看单个 chunk 的向量详情
   - 支持示例知识一键导入
   - 支持全量重建 RAG 索引脚本

4. **文章管理能力增强**
   - 管理端支持批量导入 PDF / Word 文章

5. **AI 上下文能力增强**
   - AI 问答支持会话历史
   - 支持用户手动选择私密数据参与本次问答
   - 支持返回 `references`
   - 支持 `private_context_used`
   - 首页 AI 建议支持缓存与更新时间

6. **隐私与敏感字段能力增强**
   - 用户邮箱、钱包地址、社交 open_id 已加入加密/哈希/脱敏逻辑
   - 前后端展示信息与数据库真实存储逻辑不再等同

7. **健康数据能力增强**
   - PDF 记录不再默认只能私密，可自由选择公开/保密
   - 私密记录支持基于账号内可用私钥自动解密
   - 创建/更新健康数据会影响首页 AI 建议缓存

### 2.2 对测试策略的直接影响

因此当前测试已经不能只覆盖传统 CRUD，需要新增以下测试面：

- Ollama 可用 / 不可用测试
- Qdrant 可用 / 不可用测试
- RAG 向量索引正确性测试
- chunk / vector 可视化管理接口测试
- AI 流式 SSE 事件测试
- 私密数据授权注入 AI 问答测试
- 首页 AI 建议缓存刷新测试
- 敏感字段脱敏显示与检索测试
- 批量导入 PDF / DOCX 的兼容性测试

## 7. 风险点与重点关注项

### 7.1 当前高风险点

1. **敏感字段真实值与展示值不一致**
   - 邮箱、钱包地址、open_id 已脱敏/哈希/加密
   - 搜索、展示、返回值都可能与旧版本不同

2. **AI 问答依赖外部服务**
   - Ollama 不可用时需正确返回错误
   - 流式返回中途失败时需正确终止

3. **RAG 向量链路复杂**
   - 文档导入成功不等于向量入库成功
   - MySQL 中 chunk 存在不等于 Qdrant 中 point 存在

4. **首页 AI 建议是缓存机制**
   - 公开资料/公开健康数据修改后，不再是立即同步结果
   - 需要验证失效与重建逻辑

5. **私密数据 AI 授权机制复杂**
   - 不是默认全量读取，而是用户勾选参与
   - 需要验证授权边界与使用痕迹字段

6. **PDF 公开/私密逻辑已变化**
   - 旧版默认保密，现版本允许公开
   - 原有测试结论需更新

7. **新增管理端调试能力**
   - 文档 chunk 状态查看
   - 向量详情查看
   - 这些接口属于高权限接口，需要重点测权限与正确性

### 7.2 回归重点

每次改动后，至少回归以下内容：

- 登录 / 注册
- 获取当前用户
- 健康记录创建 / 查询 / 更新 / 删除
- AI 普通聊天 / 流式聊天
- 首页 AI 建议
- 管理员新增 RAG 文档并查看 chunk 状态
- 管理员导入文章

## 12. 最终建议

针对当前版本，测试策略建议调整为：

> **以后端接口自动化 + AI/RAG 集成测试为主，前端关键链路 E2E 为辅，区块链作为保留专项。**

当前版本和上一版相比，最重要的测试重心变化是：

1. 从“传统功能测试”升级为“功能 + AI + 向量检索 + 数据隐私”联合测试
2. 从“知识库内容管理”升级为“知识库内容 + chunk + vector + 检索结果”完整闭环测试
3. 从“静态首页展示”升级为“首页 AI 建议缓存与重建机制”测试

因此，正式执行时建议优先把以下链路跑通：

- 登录 -> 健康数据 -> 首页 AI 建议
- 登录 -> AI 问答 -> 流式问答 -> 历史记录
- 管理员 -> 新增 RAG 文档 -> 查看 chunk -> 查看向量 -> AI 问答命中引用
- 管理员 -> 导入文章 / 导入知识文档 -> 前台可用
