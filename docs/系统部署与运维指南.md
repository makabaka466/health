# 健康管理系统系统部署与运维指南

## 1. 文档说明

### 1.1 文档目的
本文档用于说明健康管理系统在本地开发、测试和演示环境中的部署流程、运行依赖、配置说明、启动方式、运维检查、故障处理与备份建议。

### 1.2 适用范围
- 后端服务：FastAPI + SQLAlchemy
- 前端服务：Vue 3 + Vite + Element Plus
- 数据库：MySQL
- 区块链服务：Ganache / EVM 兼容 RPC
- AI 服务：Ollama
- 向量检索服务：Qdrant

### 1.3 目录说明
- `backend`：后端代码、接口、服务层、测试脚本；
- `frontend`：前端页面、路由、API 封装与构建产物；
- `contracts`：Solidity 智能合约与编译产物；
- `docs`：项目说明文档；
- `scripts`：辅助启动、依赖检查与运维脚本；
- `.venv`：Python 虚拟环境。

## 3. 配置说明

### 3.1 数据库配置
配置文件：

`backend/app/config.py`

默认配置如下：
- `DB_HOST=127.0.0.1`
- `DB_PORT=3306`
- `DB_USER=root`
- `DB_PASSWORD=123456`
- `DB_NAME=health`
- `DATABASE_URL=mysql+pymysql://root:123456@127.0.0.1:3306/health?charset=utf8mb4`

生产或正式演示环境建议通过环境变量覆盖默认值，避免将真实密码写入代码。

### 3.2 JWT 配置
- `SECRET_KEY`：JWT 签名密钥；
- `ALGORITHM=HS256`
- `ACCESS_TOKEN_EXPIRE_MINUTES=30`

运维建议：
- 正式环境必须修改默认 `SECRET_KEY`；
- 密钥变更会导致旧 Token 失效。

### 3.3 管理员初始账号
默认配置：
- `ADMIN_USERNAME=admin`
- `ADMIN_EMAIL=admin@health.com`
- `ADMIN_PASSWORD=admin123`
- `ADMIN_REGISTER_KEY=123`

运维建议：
- 初次部署后立即修改管理员密码；
- 避免在公开环境继续使用默认管理员口令。

### 3.4 区块链配置
默认配置：
- `WEB3_PROVIDER_URI=http://127.0.0.1:7545`
- `WEB3_RPC_TIMEOUT_SECONDS=3`
- `HEALTH_DATA_CONTRACT_ADDRESS`：健康数据合约地址；
- `HEALTH_DATA_CONTRACT_ABI_JSON`：合约 ABI；
- `WEB3_AUTO_FUND_NEW_USERS=true`
- `WEB3_AUTO_FUND_AMOUNT_ETH=10`
- `WEB3_GAS_PRICE_GWEI=2`

说明：
- 系统支持 Ganache 运行中启停；
- Ganache 未启动时，健康数据上传和加载可降级运行；
- Ganache 未启动时，注册入口会拒绝创建新用户；
- Ganache 启动后，刷新健康记录可重新触发链上验真。

### 3.5 AI 与 RAG 配置
Ollama 默认配置：
- `OLLAMA_BASE_URL=http://127.0.0.1:11434`
- `OLLAMA_MODEL=deepseek-r1:8b`
- `OLLAMA_TIMEOUT_SECONDS=300`
- `OLLAMA_EMBEDDING_MODEL=nomic-embed-text`

Qdrant 默认配置：
- `RAG_VECTOR_ENABLED=true`
- `RAG_VECTOR_BASE_URL=http://127.0.0.1:6333`
- `RAG_VECTOR_COLLECTION=health_rag_documents`
- `RAG_VECTOR_TIMEOUT_SECONDS=30`

## 4. 首次部署步骤

### 4.1 获取代码
进入项目根目录：

`C:\Users\zhiha\Desktop\杂\健康管理系统`

确认目录中包含：
- `backend`
- `frontend`
- `contracts`
- `docs`
- `scripts`

### 4.2 创建 Python 虚拟环境
在项目根目录执行：

`python -m venv .venv`

安装依赖：

`.\.venv\Scripts\pip install -r backend\requirements.txt`

### 4.3 安装前端依赖
进入前端目录：

`cd frontend`

安装依赖：

`npm install`

### 4.4 初始化数据库
确认 MySQL 服务已启动，并创建数据库：

`CREATE DATABASE health CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`

后端启动时会执行数据库初始化逻辑。若需要导入种子数据，可参考：

`backend/seed_health.sql`

### 4.5 启动依赖服务
根据需要启动：
- MySQL；
- Ganache；
- Ollama；
- Qdrant。

依赖检查脚本：

`scripts/check_runtime_deps.ps1`

带自动启动参数：

`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check_runtime_deps.ps1 -AutoStart`

## 5. 启动方式

### 5.1 一键检查并启动
推荐使用：

`start_project_checked.bat`

说明：
- 会先检查 Ollama 与 Ganache；
- 若依赖未就绪，会给出提示；
- 检查后继续调用 `start_project.bat` 启动前后端。

### 5.2 一键快速启动
可使用：

`start_project.bat`

说明：
- 检查 `.venv`、`frontend/package.json`、`node_modules`；
- 分别打开后端和前端窗口；
- 后端地址：`http://127.0.0.1:8000/docs`
- 前端地址：`http://127.0.0.1:3000`

### 5.3 手动启动后端
在项目根目录执行：

`cd backend`

`..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000`

接口文档地址：

`http://127.0.0.1:8000/docs`

### 5.4 手动启动前端
在项目根目录执行：

`cd frontend`

`npm run dev`

访问地址：

`http://127.0.0.1:3000`

## 6. 构建与发布

### 6.1 前端构建
执行：

`npm --prefix frontend run build`

构建产物目录：

`frontend/dist`

说明：
- 构建后会生成带哈希的静态资源文件；
- 若只做本地开发，可不提交构建产物；
- 若部署静态站点，可将 `dist` 目录交给 Nginx 或其他静态服务器。

### 6.2 后端运行方式
开发环境可使用 Uvicorn：

`python -m uvicorn app.main:app --host 127.0.0.1 --port 8000`

正式环境建议：
- 使用独立 Python 虚拟环境；
- 配置强随机 `SECRET_KEY`；
- 使用进程管理工具守护后端；
- 将数据库、区块链、AI 服务地址写入环境变量。

## 7. 运维检查

### 7.1 后端健康检查
访问：

`http://127.0.0.1:8000/api/health`

正常返回：

`{"status":"healthy","version":"1.0.0"}`

### 7.2 前端访问检查
访问：

`http://127.0.0.1:3000`

检查项：
- 登录页可打开；
- 注册页可打开；
- 用户登录后可进入 Dashboard；
- 管理员登录后可进入管理端。

### 7.3 Ganache 检查
默认 RPC：

`http://127.0.0.1:7545`

检查项：
- RPC 端口可访问；
- 合约地址与当前 Ganache 链一致；
- Faucet 账户有余额；
- 后端刷新健康记录时可恢复链上验真。

### 7.4 Ollama 检查
默认地址：

`http://127.0.0.1:11434`

检查项：
- Ollama 服务已启动；
- 配置模型已拉取；
- AI 问答接口可返回结果；
- 首页 AI 建议可生成或返回降级提示。

### 7.5 Qdrant 检查
默认地址：

`http://127.0.0.1:6333`

检查项：
- Qdrant 服务已启动；
- 知识库集合存在；
- RAG 检索无异常；
- 文档导入后可建立向量索引。

## 8. 日志与监控

### 8.1 系统日志
管理端提供系统日志查看能力，主要记录：
- 登录；
- 注册；
- 健康数据上传；
- 健康数据更新；
- 链上告警；
- 系统设置查看与变更；
- 用户管理操作。

### 8.2 本地日志文件
项目目录中可能存在：
- `backend/backend.log`
- `backend/backend.err.log`
- `frontend/frontend.log`
- `frontend/frontend.err.log`
- `logs`

运维建议：
- 出现接口异常时先查看后端错误日志；
- 出现页面无法访问时查看前端启动窗口；
- 出现链上异常时查看系统日志中的 `onchain_warning`。

### 8.3 重点监控项
- 后端进程是否存活；
- MySQL 是否可连接；
- Ganache RPC 是否可连接；
- Ollama 是否可连接；
- Qdrant 是否可连接；
- 磁盘空间是否足够；
- 文件上传大小是否异常增长。

## 9. 备份与恢复

### 9.1 数据库备份
建议定期备份 MySQL 数据库：

`mysqldump -u root -p health > health_backup.sql`

恢复：

`mysql -u root -p health < health_backup.sql`

### 9.2 合约信息备份
需要备份：
- 合约源码；
- 合约 ABI；
- 合约地址；
- Ganache 工作区或链状态；
- 与合约相关的部署记录。

### 9.3 用户密钥材料
系统中保存了用户加密后的私钥材料。运维时必须保护：
- 数据库备份文件；
- `SECRET_KEY`；
- 服务器访问权限；
- 管理员账号。

注意：
- 如果数据库备份和 `SECRET_KEY` 同时泄露，私钥材料存在被解密风险；
- 如果 `SECRET_KEY` 丢失，已加密私钥材料可能无法恢复。

## 10. 常见故障处理

### 10.1 后端无法启动
可能原因：
- Python 虚拟环境不存在；
- 依赖未安装；
- MySQL 未启动；
- 数据库账号密码错误；
- 端口 `8000` 被占用。

处理建议：
- 检查 `.venv\Scripts\python.exe` 是否存在；
- 重新执行 `pip install -r backend\requirements.txt`；
- 检查 MySQL 服务；
- 检查 `DATABASE_URL`；
- 更换后端端口。

### 10.2 前端无法启动
可能原因：
- Node.js 或 npm 未安装；
- `node_modules` 不存在；
- 端口 `3000` 被占用。

处理建议：
- 执行 `npm install`；
- 执行 `npm run dev`；
- 检查终端报错；
- 修改 Vite 启动端口。

### 10.3 无法注册
可能原因：
- 系统处于维护模式；
- 注册开关关闭；
- 密码长度不符合要求；
- Ganache/RPC 未启动；
- 用户名或邮箱重复。

处理建议：
- 启动 Ganache；
- 检查管理端系统设置；
- 检查后端返回的 `detail` 信息。

### 10.4 上传数据失败
可能原因：
- 用户未登录或 Token 过期；
- 文件类型不支持；
- PDF 或 Word 文件过大；
- 私密数据缺少可用私钥；
- 数据库连接异常。

处理建议：
- 重新登录；
- 检查上传文件格式；
- 压缩文件后重试；
- 查看系统日志与后端错误日志。

### 10.5 验真显示服务未启用
可能原因：
- Ganache 未启动；
- 合约地址不匹配；
- Ganache 重置导致合约数据丢失；
- 合约 ABI 与实际合约不一致。

处理建议：
- 启动 Ganache；
- 确认 `WEB3_PROVIDER_URI`；
- 确认 `HEALTH_DATA_CONTRACT_ADDRESS`；
- 重新部署合约并更新配置。

### 10.6 AI 问答不可用
可能原因：
- Ollama 未启动；
- 模型未下载；
- 模型响应超时；
- AI 开关被关闭。

处理建议：
- 启动 Ollama；
- 拉取配置模型；
- 检查 `OLLAMA_BASE_URL`；
- 在管理端检查 AI 开关。

## 11. 安全运维建议

### 11.1 账号安全
- 修改默认管理员密码；
- 禁用长期不用的账号；
- 管理员账号仅分配给可信用户；
- 定期检查系统日志。

### 11.2 密钥安全
- 正式环境必须修改 `SECRET_KEY`；
- 不要将真实密钥提交到公开仓库；
- 数据库备份应加密保存；
- 生产环境建议使用专门的密钥管理方案。

### 11.3 网络安全
- 后端管理接口不应直接暴露到公网；
- 前后端跨域地址应按实际域名配置；
- 数据库端口不应暴露给非必要网络；
- Ganache 仅建议用于本地开发或演示。
