# Backend Tests Plan

## 1. 现有测试梳理（需要 / 不需要）

### 1.1 建议保留并持续运行（需要）

- `p0/test_auth_p0.py`
  - 认证主链路、管理员用户管理能力、账号状态边界
- `p0/test_profile_health_p0.py`
  - 公开/私密资料与健康记录访问边界
- `p0/test_ai_admin_rag_p0.py`
  - AI 问答、流式输出、管理端 RAG 管理能力
- `p0/test_import_cache_resilience_p0.py`
  - 导入、缓存失效、Ollama 不可用降级
- `p0/test_async_optimization_p0.py`（新增）
  - 异步优化回归：`to_thread` 与后台索引入队

### 1.2 不建议纳入版本管理（不用）

- `tests/.tmp/*.sqlite3`
  - 运行测试时自动生成的临时数据库文件，不应作为源码版本的一部分
- `tests/**/__pycache__/`
  - Python 编译缓存文件，不应纳入版本管理

## 2. 自动化测试（代码可跑）

### 2.1 一键执行 P0

在项目根目录运行：

```powershell
backend\run_p0_tests.ps1
```

或直接：

```powershell
cd backend
..\.venv\Scripts\python.exe tests\run_p0.py
```

### 2.2 当前自动化覆盖重点

- 用户注册、登录、管理员登录
- 用户状态禁用/启用边界
- 个人资料公开/私密权限控制
- 健康记录公开/私密访问边界
- PDF 记录基础链路
- AI 问答与 SSE 流式响应
- RAG 文档管理与向量接口权限
- 导入与首页缓存失效
- 异步优化回归（`to_thread`、后台索引入队）

## 3. 手动测试（建议你执行）

以下场景更依赖真实前端交互、浏览器行为和可用性体验，建议手动验证：

1. 管理端 UI 交互
- 菜单、表格、弹窗、筛选、分页是否符合预期

2. 健康记录详情查看体验
- 公开记录点击“查看”是否直接展示
- 私密记录输入私钥后展示是否正确

3. 文档下载行为
- 点击下载是否触发浏览器下载
- 不同浏览器（Chrome/Edge）兼容性

4. 异步任务用户感知
- 导入知识库文档后是否能在短时间内看到分块/向量状态变化
- 在导入/上链期间，其他页面是否仍流畅

5. 异常提示文案
- 私钥错误、模型不可用、链不可用时文案是否易懂

---

## 4. 运行建议

1. 先执行自动化 P0，确保基础能力稳定
2. 再执行手动测试，重点验证你关心的页面和交互体验
3. 发现缺口后，优先补充到 `backend/tests/p0/`，形成可回归资产
